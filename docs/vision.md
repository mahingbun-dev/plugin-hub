# hub 链接万物 —— plugin-hub 愿景

> **The hub that links everything.**

用**微服务的视角**理解这个架构：hub 之于 agent 与工具生态，正如注册中心与服务网格之于微服务——它管发现、契约、调用、治理与观测；业务能力全部住在插件里。接入一次，处处可用：**hub 链接万物**。

## 设计哲学

两条铁律，其余全部让位：

1. **hub 本体只保证两件事：足够简单、足够稳定。** 核心不进任何业务语义，
   每加一个能力都要回答「这为什么不能是插件」。
2. **横切能力也是插件。** 包括登录鉴权在内——hub 只认权限位，鉴权本身由
   auth 插件提供，不配置就不拦。治理靠组合，不靠堆核心。

## 生态图景

以下方向按「底座是否已在仓库中」诚实标注——**已有底座**的条目指的是
plugin-hub 当前版本已提供的机制，插件本身仍需按场景实现；**方向**则是
纯愿景，机制与插件都要探索。

### 治理与安全

- **高危操作门禁**：SQL 等高危操作在插件层做门禁，拒绝 agent 的高危调用——
  审批、分级、人机回路都在插件里做，hub 只负责把调用路由过去。
  （底座已有：鉴权插件化、插件校验器 `validation_rejected`、逐调用审计。）
- **互调授权**：谁能调谁，白名单声明、按名单放行。
  （底座已有：`invokes` 声明式授权名单 + `HUB_PLUGIN_CALL_POLICY`。）

### Agent 协作（A2A）

- **基于 hub 做 A2A**：agent 与 agent、agent 与工具之间的发现与互调走同一套
  总线——身份、防环、限额、审计天然齐备。
  （底座已有：PluginGateway 同步互调、调用链贯通、熔断与并发治理。）
- **锁插件**：让 agent 像代码一样加入并发池、争抢锁——分布式锁语义做成
  插件，多个 agent 并发操作同一资源时不再互相踩踏。（方向）
- **会话上下文共享插件**：多个不同 agent 的协作与上下文共享，hub 天然的
  消息中枢位置使它适合当这个「共享黑板」。（方向）

### 触发与集成

- **Hook 自动触发**：因为有 HTTP 接入方式，可以挂到 agent 的 hook 里自动
  触发——**不需要 agent 主动调 MCP**，事件驱动而不是轮询驱动。
  （底座已有：HTTP ingress、cron / MQ 触发器、Redis Stream 事件总线。）
- **普通前后端产品互通**：不只 agent——普通的前后端产品也能接入 hub，
  让 agent 与它们互通。任何能发 HTTP 请求的系统都是 hub 的公民。
  （底座已有：HTTP ingress + MCP 双面并存，`docs/design.md` 端口表。）

### 统一规范管理

- 把原本要**一个一个适配**的工作全部规范管理：N 个工具 × M 个 agent 的
  接入矩阵，从 N×M 次胶水代码收敛为 N+M 次插件注册。契约变更可控、
  调用链可观测、权限可审计——适配不再是一次性工程，而是可运营的资产。

## 一句话

**hub 链接万物。**
